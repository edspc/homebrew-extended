# Formulae and casks

- **Formulae follow homebrew-core conventions** ([Formula Cookbook](https://docs.brew.sh/Formula-Cookbook), [Python for Formula Authors](https://docs.brew.sh/Python-for-Formula-Authors)) and stay clean under `brew style` and `brew audit --strict --online`.

- `Formula/` — one formula per file. Python applications use `Language::Python::Virtualenv`, take `url` and every `resource` from PyPI sdists (`files.pythonhosted.org`, generated by `brew update-python-resources`, never by hand) and depend on the same `python@3.x` as homebrew-core. For Go tools built from source, use the GitHub tag archive: `def fetch` runs `go mod download` (the only phase with network access), `install` builds offline with `std_go_args`; Prometheus projects set `github.com/prometheus/common/version` through `ldflags` and build with upstream's `netgo` tag from `.promu.yml` (`builtinassets` only matters for binaries that serve the web UI).

- Upstream prebuilt executables may be used when that is the chosen distribution
  method. Select the supported OS/CPU artifacts, verify every downloaded SHA-256,
  and install the command without compiler-only dependencies. The existing
  `bitbucket-cloud-mcp` formula demonstrates this path.
- Casks live in `Casks/` and follow the [Cask Cookbook](https://docs.brew.sh/Cask-Cookbook).
  Match artifact stanzas and platform constraints to the actual upstream package.
- Bottle invalidation and publication are governed by the
  [Change lifecycle](lifecycle.md); do not duplicate bottle checksums by hand.
