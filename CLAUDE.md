# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Homebrew tap `edspc/extended` (`brew install edspc/extended/<formula>`). Formulae live in `Formula/`. Bottles are built by `brew test-bot` in pull requests and published to GitHub Packages (`https://ghcr.io/v2/edspc/extended`) by `brew pr-pull`.

## Hard rules

- **The repository is public.** No tokens, keys, personal emails or other private data anywhere: formulae, workflows, commit messages, git history. GitHub Actions logs are public too: secrets reach steps only through `env:`, and derived values are masked (`::add-mask::`).
- **Formulae follow homebrew-core conventions** ([Formula Cookbook](https://docs.brew.sh/Formula-Cookbook), [Python for Formula Authors](https://docs.brew.sh/Python-for-Formula-Authors)) and stay clean under `brew style` and `brew audit --strict --online`.
- **Bottles come only from `brew pr-pull`.** Never write `bottle do` checksums by hand and never land a formula change with the GitHub merge button: the publish workflow uploads the bottles, adds the bottle commit and pushes to `main`. A change that invalidates the published bottles (new version, `revision`, dependency) drops the `bottle do` block, so a formula that lands without bottles builds from source instead of pouring a stale bottle.
- **Workflows follow the `brew tap-new` templates** (`.github/workflows/tap-new-*.yml` in Homebrew/brew): `permissions: {}` at the top and the minimum per job, actions pinned to a commit SHA with the version in a comment (Dependabot updates them), no `pull_request_target`. When updating, diff against the current templates instead of editing ad hoc.
- **README.md is the user guide** (tapping and installing). Update it together with changes that affect users. No other documentation unless explicitly asked.

## Commands

```bash
brew style edspc/extended                               # RuboCop with Homebrew's cops, plus actionlint/shellcheck for workflows
brew audit --strict --online --tap=edspc/extended       # formula audit (add --new for a new formula)
brew readall --aliases edspc/extended                   # every formula loads
brew livecheck --tap=edspc/extended                     # newest upstream versions
brew install --build-from-source edspc/extended/<formula>
brew test edspc/extended/<formula>
brew linkage --test edspc/extended/<formula>
brew update-python-resources edspc/extended/<formula>   # regenerate the resource blocks of a Python formula
```

The verification gate is `style`, `audit --strict --online`, a build from source and `brew test` for every changed formula. CI (`tests.yml`) runs the same through `brew test-bot`.

## Layout

- `Formula/` — one formula per file. Python applications use `Language::Python::Virtualenv`, take `url` and every `resource` from PyPI sdists (`files.pythonhosted.org`, generated by `brew update-python-resources`, never by hand) and depend on the same `python@3.x` as homebrew-core. Go tools build from the GitHub tag archive: `def fetch` runs `go mod download` (the only phase with network access), `install` builds offline with `std_go_args`; Prometheus projects set `github.com/prometheus/common/version` through `ldflags` and build with upstream's `netgo` tag from `.promu.yml` (`builtinassets` only matters for binaries that serve the web UI).
- `.github/workflows/tests.yml` — `brew test-bot` on pushes to `main` and on pull requests: tap syntax (style, audit, readall), then build, test and bottle the changed formulae on `macos-26`, `xcode-27` (macOS 27) and on Linux (`ubuntu-latest` in the `ghcr.io/homebrew/brew` container); bottles are uploaded as workflow artifacts.
- `.github/workflows/publish.yml` — manual (`workflow_dispatch`, pull request number and optionally its expected head SHA): `brew pr-pull` downloads the pull request's bottles, uploads them to GitHub Packages, adds the bottle commit, attests build provenance and pushes to `main`. `pr-pull` appends `Closes #N.` to the last commit of the pull request, which closes it once pushed; delete its branch afterwards.
- `.github/workflows/autobump.yml` — daily `brew bump` opens version bump pull requests from branches in this repository.
- `.github/dependabot.yml` — weekly grouped updates of the pinned actions.

## Landing changes

1. Change the formula on a branch and open a pull request.
2. Wait until `brew test-bot` is green on all runners.
3. Run the `brew pr-pull` workflow (Actions → brew pr-pull → Run workflow) with the pull request number. `workflow_dispatch` only sees workflows on `main`, so changes to `publish.yml` itself land first.

Pull requests without formula changes (workflows, documentation, Claude settings) are merged normally.

## Stack notes (verified when these rules were written)

- Homebrew 6 requires tap trust for non-official taps: installing by the full name (`brew install edspc/extended/<formula>`) trusts that formula, short names need `brew trust` first.
- macOS bottles are built on `macos-26` (`arm64_tahoe`), as in the `brew tap-new` template, and additionally on macOS 27 (`arm64_golden_gate`); older macOS versions build from source. GitHub offers macOS 27 only as the public preview image `xcode-27`; there is no `macos-27` label yet, so switch to it once it exists. actionlint reports `xcode-27` as an unknown label, which `brew style` ignores.
- Pull requests opened by `autobump.yml` with `GITHUB_TOKEN` do not trigger `tests.yml` (GitHub does not start workflows for events caused by `GITHUB_TOKEN`); close and reopen the pull request to run CI.
- Cloud sessions: `brew` refuses to run as root (use a separate user with the default prefix `/home/linuxbrew/.linuxbrew`), Homebrew's portable Ruby trusts only its own `libexec/cert.pem` (append the session's proxy CA bundle there), and `--online` audits report URLs outside the session's network policy (GitHub repositories not attached to the session, some project sites) as unreachable (HTTP 403). GitHub tag archives of such repositories cannot be downloaded either, but `git clone` works and `git archive --format=tar --prefix=<repo>-<version>/ <tag> | gzip -cn` reproduces the archive byte for byte: use it for the `sha256` and seed `brew --cache -s <formula>` with it to build locally.
- `Homebrew/actions/git-user-config` (publish and autobump) commits as the GitHub user who triggered the run, with the public email of their profile if one is set, otherwise their noreply address. Keep the profile email private.

## Git conventions

- **No Claude attribution anywhere in git history.** No `Co-Authored-By:` trailer, no `Claude-Session:` line, no `https://claude.ai/...` URL in commits; no "Generated with Claude Code" footer or Claude link in pull requests. Enforced by `.claude/settings.json`.
- **Commits are unsigned and authored as the repo owner with their GitHub noreply address** (`<id>+<login>@users.noreply.github.com`, the name and id from their GitHub profile), never a personal email: the repository is public. Cloud sessions reset `git config` on every fresh clone, so set it in the environment's setup script (`git config --global commit.gpgsign false`, likewise `tag.gpgsign`, `user.name`, `user.email`), or pass `--no-gpg-sign` and `-c user.name=… -c user.email=…` per commit. `GIT_AUTHOR_*` and `GIT_COMMITTER_*` environment variables override `git config`; check them too.
- **No binary files in git.** Bottles live in GitHub Packages only.
- Formula commits use Homebrew's message style, the same as `brew bump` and `brew pr-pull` produce, one formula per commit: `foo 1.2.3` (version bump), `foo 1.0 (new formula)`, `foo: delete`, `foo: <change>`; `foo: update 1.2.3 bottle.` comes from `pr-pull`. Everything else uses Conventional Commits (`ci:`, `chore:`, `docs:`).
